# 对话面板增强功能用户指南

## 1. 功能概览

对话面板增强版聚焦四件事：更稳定的流式生成、更清晰的思考与输出展示、更可控的会话分支，以及更可配置的调试与模型源。

用户将可以：

- 在生成过程中继续准备下一条消息，不必等待当前输出结束。
- 主动暂停或中止当前生成，并在对话中看到明确的灰色中断提示。
- 在外部请求失败时看到红色失败提示，且保留已生成的上下文以便后续继续。
- 折叠查看思考过程与工具调用，仅在 debug 模式下展开更详细的输入输出。
- 编辑会话标题、编辑历史消息、对助手输出执行 retry，并在多个分支版本之间切换。
- 在设置面板里开启 debug 模式，并选择或管理 API 源。

本功能的“真实行为标准”如下：

- 默认界面隐藏系统消息与详细 trace 输入输出。
- 思考过程与最终回答严格分离：最终回答区域不显示 `think` 文本，`think` 文本进入 ReAct trace。
- 思考过程会在 ReAct 推理过程中实时流式追加，而不是等整轮结束后一次性出现。
- 非 debug 模式下仍保留完整的 thinking 文本；debug 模式只额外显示系统消息与工具输入输出。
- 中断、失败、retry、编辑都不会覆盖旧版本，而是形成可回溯的分支树。

## 2. 使用方式

### 2.1 新建与管理会话

1. 点击左侧加号创建新会话。
2. 如果当前会话仍然是空白会话，系统会直接复用它，而不是继续新增空白会话。
3. 当第一轮问答结束后，系统会自动生成标题；你也可以直接在标题区域手动编辑。

### 2.2 生成中的操作

1. 发送消息后，输入框保持可编辑，你可以提前准备下一条消息。
2. 此时发送按钮切换为“暂停/中止”按钮。
3. 点击后，当前输出停止，并在该条 assistant 消息下方显示灰色中断提示。
4. 中止只会终止当前流式生成，不会发送输入框里的草稿；草稿内容会完整保留，用户可以继续编辑。
5. 如果是后端请求失败，则显示红色失败提示；当前已经生成的一半内容会作为一个完整的历史版本保留在数据库中。
6. 中断后不会出现单独的“继续生成”按钮；用户后续发送的新消息，会直接基于当前保留下来的上下文继续对话。
7. 输入框下方会显示最多三个“快捷 skill”按钮；它们优先取你最近在 `@` 技能面板里选中过的 skill，不足三个时再按默认顺序补齐。
8. 点击快捷 skill 会自动把对应的 `@技能名` 补入输入框，便于连续使用常用 persona。
9. 当前版本的聊天输入区暂不支持附件上传，因此上传按钮默认隐藏。

### 2.3 查看思考、系统消息与调试信息

1. 助手输出分为“最终回答”和“思考过程”两部分。
2. 思考过程会在 ReAct 循环进行时实时流式出现，顺序通常表现为“循环开始 -> think -> 工具 -> think -> 工具 -> think -> 循环结束”。
3. 思考过程默认可折叠；展开后，在非 debug 模式下也会显示完整 think 文本。
4. 打开 debug 模式后，可进一步查看系统消息、工具输入输出和更详细的 trace。

### 2.4 选择 API 源

1. 对话面板顶部或输入区附近会提供 provider 下拉栏。
2. 你可以为当前 session 直接切换 API 源，而不需要进入全局设置。
3. 如果选择“自动降级”，系统会在远程 API 出现服务端或网络问题时，按 provider 面板中展示的优先顺序自动切换到下一个可用源。
4. 如果未开启自动降级，则即使当前 provider 报错，也不会自动切换到其他源。
5. 全局设置页负责管理“有哪些 API 源可用”，包括名称、地址、明文密钥、模型名和优先级；支持拖拽调整顺序。
6. LLM 的通用设置，如温度、最大迭代次数、默认 system prompt，也统一在同一设置面板中编辑，并写入 output 目录下的 YAML 文件。
7. 这次 YAML 化只覆盖 LLM API 相关配置；日志、数据库、embedding 等其他现有 env 配置暂时保持不变。

### 2.5 编辑与分支

1. 每条 user 或 assistant 消息下方提供编辑按钮。
2. 编辑历史 user 消息后，会从该位置重新生成新的后续分支；这个新分支和原分支会并存。
3. 对 assistant 消息点击 retry，会在同一父节点下生成新的版本；其展示方式与编辑产生的分支一致。
4. 只要某个位置存在多个版本，无论这些版本来自“编辑历史消息”还是“retry”，界面都会以标签页式版本组呈现，并提供左右切换按钮，用于在不同版本间来回查看。

### 2.6 侧边栏说明

1. 左侧边栏底部当前仅保留设置入口。
2. 用户信息区尚未开放，因此不会在设置按钮旁显示头像或个人资料入口。

## 3. 状态说明与异常表现

| 状态 | 前端表现 | 后续行为 |
|------|---------|---------|
| generating | assistant 正在流式输出，按钮显示“暂停/中止” | 可继续输入下一条草稿 |
| interrupted | 当前消息下方出现灰色中断提示 | 半成品消息保留；下次发送会基于当前上下文新增下一条消息 |
| failed | 当前消息下方出现红色失败提示 | 可 retry，也可基于当前上下文继续对话 |
| completed | 正常显示最终回答 | 可编辑、可 retry |

补充规则：

- 系统消息默认隐藏，仅在 debug 模式展示。
- 最终回答区域永远不显示 `<think>` 标签或 think 文本；这些内容只允许出现在 ReAct trace 中。
- 如果某一轮没有工具调用，则 trace 可以退化为“循环开始 -> think -> 循环结束”；如果某一步没有显式 think，也允许直接出现工具步骤。
- 如果切换到旧分支，界面会恢复该分支对应的上下文，而不是自动跳回最新输出；编辑产生的分支与 retry 产生的分支都遵守同一套切换规则。
- 当流式输出中途失败且开启自动降级时，系统会自动创建一个新的分支版本，用降级后的 provider 重新生成；旧的失败版本仍可回看。
- 多 API 源开启自动降级时，当前会话会记住本次实际使用的 provider，便于问题排查。
