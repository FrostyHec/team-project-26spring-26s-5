# Agent Memory 用户指南

## 功能概览

Agent Memory 让大模型通过工具把长期记忆保存为 Markdown 文件。每条记忆按主题拆分到独立文件，文件头带 YAML Frontmatter 元数据，正文保存实际内容。

默认行为如下：

- 记忆目录位于运行时数据目录下的 `output/agent_memory/`
- 模型通过工具执行“列出主题、读取主题、创建记忆、追加更新、重写主题”
- 同一主题应尽量保持单文件，避免重复创建同义主题文件
- 用户与开发者可直接查看 `.md` 文件，便于审计和迁移

## 使用方式

### 1. 让 agent 记住一条新事实

用户用自然语言明确提出“请记住……”后，agent 应创建一个新主题文件，写入：

- 可读标题
- tags
- summary
- 正文内容

### 2. 查看已有记忆主题

当用户询问“你记得什么”或希望浏览记忆时，agent 应列出主题摘要，而不是一次性返回所有文件全文。

主题列表至少应包含：

- filename
- title
- tags
- summary
- last_updated

### 3. 读取某个主题的完整记忆

当用户指定某个主题后，agent 应读取对应 `.md` 文件并基于正文回答，而不是猜测旧内容。

### 4. 更新已有主题

更新分为两类：

- `append`：在正文末尾追加新条目，适合日志式增长
- `rewrite`：重写正文，适合整理合并旧内容；执行前必须先读取当前文件，并自动保留 / 更新元数据与备份

## 边界与错误行为

- 如果目标主题不存在，工具返回明确错误，并提示先列出主题或新建文件。
- 如果新建文件名已存在，工具拒绝覆盖，并提示改用更新工具。
- 如果文件名包含路径分隔符、`..` 或非法字符，后端必须拒绝，不能把用户输入直接当路径。
- 如果运行在 `db_path=':memory:'` 的测试环境，记忆文件必须写入临时目录，不能污染真实 `output/`。
- 如果执行 `rewrite`，系统必须先生成备份，再写入新正文；一旦写入失败，应保留旧文件。
- 主题列表必须忽略 `.backup/` 和非 Markdown 文件，避免把备份当成正常记忆。
